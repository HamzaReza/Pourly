# Decisions and deviations

This file records every owner-approved deviation from `docs/SPEC.md` and every decision taken while
building. Where the spec and this file disagree, this file wins.

## Owner-approved deviations

| #   | Topic                        | Spec says                      | Decision                                                                                                                                                                                         | Reason                                      |
| --- | ---------------------------- | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------- |
| O1  | Package manager              | npm                            | **yarn classic 1.22.22**. `yarn.lock` is the only lockfile; no `package-lock.json`. ## Phase 2 decisions (game core)

| #     | Topic                         | Decision                                                                                                                                                                                                                                                                                                                                                | Reason                                                                                                                                                                                                                                                                                                         |
| ----- | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P2.1  | `CAPACITY` location           | Moved to the platform-free `src/config/game.ts` (with `MAX_TUBES = 16` and `PALETTE_SIZE = 14`); `src/config/constants.ts` re-exports it.                                                                                                                                                                                                               | `constants.ts` imports `env.ts` → `expo-constants`, which `src/game` (pure) and the `tsx` level script cannot load.                                                                                                                                                                                            |
| P2.2  | Solver off the JS thread      | **Cooperative chunking**, not a Worklets runtime. Solver and generator are generator functions that `yield` every 24 nodes; `createTask(work).step(budgetMs, now)` runs units until the next one would overrun (based on the slowest unit seen). `runTaskChunked` / `solveChunked` take an injected clock and `yieldFn`. Explicit DFS stack.            | Testable in Jest and `tsx` with the same code, no serialization or shared-memory constraints of a separate runtime (boards and the level table would have to be copied across), deterministic (node budgets, not time, bound every search). Measured max slice 8.19 ms (p99 7.9 ms) on an M1 Pro, 8 ms budget. |
| P2.3  | Canonical hash                | One char per segment (`a..n` revealed, `A..N` hidden), tube keys sorted with the default string sort and joined by `\|`.                                                                                                                                                                                                                                | Tube order irrelevant, hidden state included, stable across engines.                                                                                                                                                                                                                                           |
| P2.4  | Solver pruning                | Skips pointless moves, pours into any empty tube except the first one (same canonical state), and the immediate reversal of the previous pour **only when it revealed nothing** (the result is then one pour from the grandparent). Cross-checked against an unpruned BFS on 400 small boards: same solvable verdicts, optimal par proven.              | Keeps the search complete while cutting duplicate work.                                                                                                                                                                                                                                                        |
| P2.5  | Move ordering                 | Score: +150 for completing a tube, +50 onto a matching top (+ the target's run), +20 for moving the whole run (+10 empties the source, +15 reveals a hidden segment), −10 for splitting a run, −20 into an empty tube. Stable sort by score, then by `(from, to)` index.                                                                                | Spec §7.1 priorities. Weight variants (shorter source, pure targets, larger reveal bonus) changed total nodes by under 4% on 509 boards.                                                                                                                                                                       |
| P2.6  | Par                           | `improveSolution` is branch and bound: depth-first with the bound set to one pour shorter than the best solution, tightened on every new solution, pruned with an admissible lower bound (color changes inside tubes + extra tubes per bottom color) and a depth-aware visited map. Budget 60,000 nodes (`IMPROVE_NODE_BUDGET`).                        | Deterministic short par; exhausting the budget-free search proves optimality.                                                                                                                                                                                                                                  |
| P2.7  | Hidden segments in the solver | The solver sees true colors but moves only through `rules.ts`: hidden segments break runs and flip when exposed exactly as in play. Hidden flags are part of the hash.                                                                                                                                                                                  | Spec §7.1; hints work on mystery levels.                                                                                                                                                                                                                                                                       |
| P2.8  | Hidden count                  | Exactly `round(hiddenRatio × eligible slots)` hidden segments, chosen by shuffle (not a per-segment coin flip). Ratios are stored as whole permille.                                                                                                                                                                                                    | Predictable difficulty per level; integer math.                                                                                                                                                                                                                                                                |
| P2.9  | Palette per level             | Each level picks its `colors` palette ids by seeded shuffle of all 14.                                                                                                                                                                                                                                                                                  | Early levels are not always the same three colors.                                                                                                                                                                                                                                                             |
| P2.10 | Hard levels: paired-top deal  | Boards with one empty tube top every tube with a same-colored pair (one pair per color, shuffled) over a uniform shuffle of the other segments; hidden segments only below the pair. Two-empty-tube boards use the plain uniform shuffle of spec §7.2.                                                                                                  | A uniform shuffle with one empty tube is solvable 0–2.5% of the time from 8 colors up (measured on 200 seeds per level), so 24 of 30 hard levels fell back to two empty tubes and lost their identity. With paired tops only level 200 falls back. Validation is unchanged.                                    |
| P2.11 | Extra validation              | Besides spec §7.2 checks, the first solution must be found within `HINT_NODE_CAP` (40,000) nodes. A tube that is full and one true color (even if partly hidden) counts as complete at start.                                                                                                                                                           | A hint on the opening position always succeeds. Rejected about 1 candidate in 300.                                                                                                                                                                                                                             |
| P2.12 | `minSolutionLength`           | Per band: 1–3: 4, 4–10: 6, 11–24: 10, 25–60: 14, 61–150: 18, 151+: 22. Checked against par (after improvement), not the first solution.                                                                                                                                                                                                                 | Stricter reading of "not trivially solved". Lowest par per band: 7, 10, 13, 14, 21, 24.                                                                                                                                                                                                                        |
| P2.13 | Difficulty ramps              | Colors step evenly across each band (`min + floor(offset × steps / span)`); hidden ratio ramps linearly in permille. The 151+ band ramps over 151–300 (12 colors to 200, 13 to 250, 14 from 251; hidden 0.30 → 0.40) and holds its maximum afterwards. Hidden ratio drops at the band boundary 60 → 61 as the spec table implies.                       | Spec §7.3 bands; "151+" has no end.                                                                                                                                                                                                                                                                            |
| P2.14 | Fallback config               | One extra empty tube; if that exceeds 16 tubes (14 colors + 3), one color is dropped instead. The fallback is recorded in the level (`config.fallback`).                                                                                                                                                                                                | Spec "max 16 tubes".                                                                                                                                                                                                                                                                                           |
| P2.15 | Level codec                   | `1;<id>;<level>;<seed>;<capacity>;<colors>;<empty>;<hidden‰>;<flags>;<minSolution>;<par>;<tubes>` (base 36, flags bit 0 hard, bit 1 fallback; tubes comma-separated, one char per segment). The full config is stored, so decoding never depends on `difficulty.ts`. Decode validates every field, color counts and no hidden top.                      | Exact round trip; 300 levels = 30.5 KB.                                                                                                                                                                                                                                                                        |
| P2.16 | `Level.seed`                  | The seed that produced the board (`levelSeed(n) + attempt`); `levelSeed(n)` = FNV-1a of `pourly:level:<n>`.                                                                                                                                                                                                                                             | Regenerates the same board directly.                                                                                                                                                                                                                                                                           |
| P2.17 | Runtime levels (> 300)        | `getLevel(n)` generates synchronously and caches the last 4; `createLevelTask(n)` / `createGenerateTask` give the chunked form for idle-time pre-generation (phase 5).                                                                                                                                                                                  | Spec §7.4.                                                                                                                                                                                                                                                                                                     |
| P2.18 | Daily config                  | `level = 0`, id `daily-YYYY-MM-DD`, colors 8–10 picked by the date's seed, hidden ratio 0.25, 2 empty tubes, `minSolutionLength` 14 (band 25–60). Salt `pourly:daily:v1`.                                                                                                                                                                               | Spec §7.6 "mid-high, mystery on".                                                                                                                                                                                                                                                                              |
| P2.19 | Streak rules                  | Reward on every first completion of a new day. VIP freeze: exactly one missed day, streak > 0, and `streakFreezeWeek` ≠ the ISO week of **today** (the completion day); it then stores that week. An unreadable `lastDailyDate` counts as a first completion. `currentStreak(state, today, isVip?)` keeps showing a streak a VIP freeze can still save. | Spec §11 / §7.6. Dates are local `YYYY-MM-DD` strings, so a timezone change only changes which day "today" is.                                                                                                                                                                                                 |
| P2.20 | Stars                         | `ceil(par × 7 / 5)` and `par × 2` in integer math.                                                                                                                                                                                                                                                                                                      | No float rounding at the boundaries.                                                                                                                                                                                                                                                                           |
| P2.21 | Pointless move                | A pour of a tube's whole contents (one revealed run) into an empty tube. A uniform tube with a hidden segment is not pointless: pouring it reveals that segment.                                                                                                                                                                                        | Spec §6 "uniform tube onto an empty tube", consistent with hidden segments not counting toward runs.                                                                                                                                                                                                           |
| P2.22 | Illegal pours and undo        | `applyPour` throws on an illegal move (callers check `canPour`). Boards are immutable and share untouched tubes, so undo restores the previous snapshot (`createHistory` / `pushMove` / `undo`), reveal state included.                                                                                                                                 | Exact undo without inverse operations.                                                                                                                                                                                                                                                                         |
| P2.23 | `getHint` with no answer      | Returns null when the board is won, unsolvable, or no solution was found within 40,000 nodes. Phase 5 decides the UX (no hint consumed).                                                                                                                                                                                                                | A guessed move could lead the player into a dead end.                                                                                                                                                                                                                                                          |
