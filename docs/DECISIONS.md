# Decisions and deviations

This file records every owner-approved deviation from `docs/SPEC.md` and every decision taken while
building. Where the spec and this file disagree, this file wins.

## Owner-approved deviations

| #   | Topic                        | Spec says                      | Decision                                                                                                                                                                                         | Reason                                      |
| --- | ---------------------------- | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------- |
| O1  | Package manager              | npm                            | **yarn classic 1.22.22**. `yarn.lock` is the only lockfile; no `package-lock.json`. Expo packages are added with `npx expo install` (which runs yarn because of `yarn.lock`).                    | Owner preference.                           |
| O2  | Firebase SDK                 | `@react-native-firebase/*`     | **Firebase JS SDK** (`firebase`) plus `@react-native-google-signin/google-signin`. Config comes from `EXPO_PUBLIC_FIREBASE_*`, so there is no `google-services.json`.                            | Owner preference; no native Firebase setup. |
| O3  | Offline cache                | Firestore offline persistence  | The JS SDK has no Firestore offline persistence on React Native, so the persisted Zustand store is the offline cache and pending cloud pushes are queued there.                                  | Consequence of O2.                          |
| O4  | Purchase fulfillment         | Server fulfillment, default on | `USE_SERVER_FULFILLMENT = true` in `src/config/constants.ts`. Requires the Firebase **Blaze** plan.                                                                                              | Owner decision.                             |
| O5  | Signed-in vs guest purchases | —                              | Signed-in purchases are fulfilled only by the server; guest purchases are fulfilled on the device. Both paths are keyed by the store transaction id.                                             | Avoids double grants.                       |
| O6  | Account deletion             | —                              | Goes through an authenticated `deleteMyAccount` callable (phase 9). Privacy, terms and delete-account pages live in Firebase Hosting `public/` (phases 9/10).                                    | Play requirement; single code path.         |
| O7  | Consumable refunds           | —                              | A refund writes a negative grant; balances are floored at 0 (phase 9).                                                                                                                           | Never produce negative inventory.           |
| O8  | Coin security                | —                              | Coin balances remain client-side and spoofable. Accepted for v1: single-player game, no leaderboards or trading, and purchased value is re-granted from the server ledger for signed-in players. | Cost/benefit for v1.                        |
| O9  | `functions/`                 | —                              | A separate package. Root `tsc`, ESLint and Jest exclude it (already configured in phase 1).                                                                                                      | Own toolchain and Node target.              |
| O10 | Process                      | Autonomous build               | The owner reviews after each phase.                                                                                                                                                              | Owner preference.                           |
