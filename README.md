# Pourly

**Pourly: Water Sort Puzzle** is a hybrid-casual colour-sort puzzle for **Android**, built with
Expo and React Native. Pour liquid between tubes until every tube holds a single colour. A meta
layer (daily challenge, streaks, daily gifts, coins, themes, hard levels, stars) sits on top. The
game is fully playable offline and as a guest; Google sign-in with Firebase cloud save is
optional.

Developer: Infratek Systems · Package: `com.pourly.water.app` · Platform: **Android only**.

## Features

- **Core puzzle**: 300 precomputed, solver-verified levels (generated by `yarn gen:levels`), then
  endless runtime-generated levels; difficulty ramps from 3 to 14 colours and up to 16 tubes;
  mystery levels with hidden segments; a **hard level** every 10th level (2× coins).
- **Instant feel**: level 1 opens straight from the splash (no onboarding screens), next level
  prepared during the win animation, restart without a spinner.
- **Help tools**: 3 free undos per attempt, hints from the built-in solver, an extra tube, skip a
  level with a rewarded ad when stuck.
- **Meta layer**: daily challenge with a streak and calendar, a 7-day daily gift cycle with a chest,
  coins and stars, 8 themes (Classic free; Ember, Sunset, Forest, Candy, Neon for coins; Aurora
  from the Starter Pack; Gold for VIP).
- **Monetization**: AdMob rewarded and interstitial ads (strict caps, after level 5, Google UMP
  consent), RevenueCat purchases (coin packs, Remove Ads, Starter Pack, VIP weekly/monthly).
- **Accounts (optional)**: Google sign-in, Firestore cloud save with a conflict-free merge,
  server-side purchase fulfillment by a Cloud Function, in-app and web account deletion.
- **Local reminders**: daily, streak, gift and comeback notifications planned on the device (no push
  service).
- **International and accessible**: 13 languages (en, es, pt-BR, fr, de, it, ru, tr, id, ar, hi,
  ja, ko), RTL for Arabic, colour-blind symbols, reduced motion, screen-reader labels, 44 dp touch
  targets, WCAG AA contrast.
- **Performance**: Skia rendering with cached pictures, UI-thread animation (Reanimated 4 /
  Worklets), adaptive quality.

## Architecture

```
app/              Expo Router routes: index (Home), game, daily, shop, themes, settings,
                  dev-stress (dev builds only), _layout (root: hydration, idle start-up, hosts)
src/game/         Pure game core: rules, solver, generator, difficulty, levelCodec, daily, stars,
                  economy, gifts, freeCoins, starterPack, themeUnlocks, tutorial, task (chunking),
                  levels.generated.ts (300 encoded levels)
src/render/       Skia board: Board, TubeLayer, PourLayer, EffectLayers, layout, palette, themes,
                  scene/symbols/sprites builders, anim/ (pour frames, effects, timing), hero
src/state/        Zustand stores (progress, settings, game, cloud), models, reducers, migrations,
                  game/meta flows, level and daily loaders, debounced storage, hydration
src/services/     ads (+ AdMob, mock, scheduler, consent), iap (+ RevenueCat, mock, fulfillment),
                  auth, Google sign-in, firebase, cloud save/merge, grants, notifications
                  (+ planner, prompt), audio, haptics, review, analytics
src/ui/           Design tokens, shared components, overlays, per-screen components
src/i18n/         i18next instance, locales/<lang>.json, number/date formatting
src/config/       economy, products (re-exports shared/), ads, game, env, constants
src/utils/        dates, calendar, perf (FPS), dev-only logger
shared/           products.ts: the product → grant table shared with functions/
functions/        Cloud Functions package (Node 22): revenuecatWebhook, deleteMyAccount
firebase/         Firestore rules and indexes, rules-test package (Vitest + emulator)
public/           Firebase Hosting: landing, privacy policy, terms, account deletion, 404
scripts/          generate-levels.ts, generate-sounds.mjs, write-hosting-config.mjs
assets/           images (launcher/splash icons, temporary until phase 11) and generated sounds
__tests__/        Jest suites for the app; test-utils/ holds fakes shared by the suites
docs/             spec, decisions, setup guides, legal templates, checklists
store-listing/    Play store listing drafts per locale
```

**Pure game core.** `src/game/` has no React, React Native or Expo imports, so it runs in Jest and
in the `tsx` level script unchanged. Boards are immutable; undo restores snapshots. The solver and
generator are generator functions that yield every few nodes and run through a cooperative task
runner in ~8 ms slices on the JS thread (DECISIONS P2.2), so hints and runtime levels never block a
frame. Levels 1–300 are generated offline, verified solvable and stored as compact strings.

**Rendering.** One Skia canvas draws the board. Static layers (background, glass, each tube's
liquid) are recorded once as `Picture`s and re-recorded only for tubes that change. Gestures
(Gesture Handler 3) resolve taps on the UI thread against a mirror of the board; the JS thread
stays the source of truth and commits a pour before its animation starts. Pours, confetti,
sparkles and glows animate on the UI thread from shared values (no React render per frame).
Quality and reduced-motion switches thin out effects; an auto mode measures frame times and
downgrades once.

**State and persistence.** Zustand 5 stores persisted to AsyncStorage (`pourly.progress`,
`pourly.settings`, `pourly.game` for resumable level and daily sessions, `pourly.cloud` for sync
bookkeeping) with versioned, tested migrations and sanitizing merges, so corrupt storage never
blocks start-up. All economy maths are pure functions guarded against clock rollback.

**Services.** Native modules (AdMob, RevenueCat, Google Sign-In, notifications, store review,
Firebase) load lazily with `import()` after the first frame, behind interfaces with mocks for Expo
Go, Jest and builds without keys. Cloud features switch off cleanly when their config is missing.

## Setup

Prerequisites: Node.js 20.19+ (developed on 22.23), **Yarn classic 1.22.x** (`yarn.lock` is the
only lockfile; do not use npm or pnpm), Android Studio with an emulator or a device, an
[EAS](https://expo.dev/eas) account for cloud builds, and a JDK 21+ only for the Firestore rules
tests.

```bash
yarn install
cp .env.example .env     # fill in what you have; the game runs with every value empty
yarn android             # builds and installs the development client (expo run:android)
yarn start               # Metro for an already installed development client
```

Add Expo / React Native packages with `npx expo install <pkg>` so versions stay aligned with the
SDK. The `functions/` and `firebase/` folders are separate yarn packages (`yarn install` inside
each).

> **The Android package id `com.pourly.water.app` is permanent once the app is published on Google
> Play.** Change `ANDROID_PACKAGE` only before the first upload.

reads them through `src/config/env.ts`. Values are baked in at build time.

## Development build and release-mode testing

A development build (`expo-dev-client`) is required: AdMob, RevenueCat, Google Sign-In, Skia and
notifications are native modules. Expo Go only works for quick UI checks (mock ads and purchases,
no sign-in).

| EAS profile   | Output        | Use                                                                                                            |
| ------------- | ------------- | -------------------------------------------------------------------------------------------------------------- |
| `development` | APK, internal | Development client (`eas build --platform android --profile development`, or `yarn android`).                  |
| `preview`     | APK, internal | **Release mode** (no `__DEV__`, minified, Hermes bytecode) with Google test ad units: performance testing.     |
| `production`  | AAB, store    | Store build; `autoIncrement` version code, app version source remote. `eas submit` targets the internal track. |

**Measuring performance:** never judge frame rate in a development build (dev mode, JS debugging
and the dev menu slow it down). Build `preview`, install it on a low-end phone and follow
`docs/MANUAL_TEST_CHECKLIST.md` §1 (`adb shell dumpsys gfxinfo`, memory over 20 minutes). In a
development build, long-press the level title for the FPS overlay, and open the stress screen
(`app/dev-stress.tsx`, a button on Home in dev builds) for 16 tubes / 14 colours with automatic
pours.

Local release build without EAS: `yarn prebuild:android`, then `cd android && ./gradlew
assembleRelease` (signed with the debug key by default).

## Purchases and ads

**Which provider runs**

| Build                                         | Purchases (`src/services/iap.ts`)               | Ads (`src/services/ads.ts`)                                     |
| --------------------------------------------- | ----------------------------------------------- | --------------------------------------------------------------- |
| Expo Go                                       | Mock store ("TEST PURCHASE" sheet)              | Mock ads ("TEST AD (mock)")                                     |
| Development build, no RevenueCat key          | Mock store                                      | Mock until level 5, then AdMob test units once consent allows   |
| Development build with the key                | RevenueCat (sandbox / license testers)          | Same as above                                                   |
| `preview` (release mode)                      | RevenueCat with the key, otherwise unavailable  | None until level 5, then AdMob **test** units after consent     |
| `production` with the key and ad unit ids     | RevenueCat                                      | None until level 5, then AdMob production units after consent   |
| Release build missing the key / an ad unit id | Shop shows "Store unavailable"; nothing crashes | That ad format stays off (warning logged in development builds) |

Mock purchases (Remove Ads, Starter Pack, VIP) are remembered on the device under
`pourly.iapMock`, so they survive restarts and Restore Purchases can bring them back. "Pending
payment" completes about four seconds later, like a real pending payment.

**Products** (`shared/products.ts`, the single table used by the app and the Functions):

| Id                                      | Kind                      | Grants / entitlement                         |
| --------------------------------------- | ------------------------- | -------------------------------------------- |
| `coins_500`, `coins_1500`, `coins_4000` | Consumable                | 500 / 1500 / 4000 coins                      |
| `remove_ads`                            | Non-consumable            | Entitlement `no_ads` (no interstitials)      |
| `starter_pack`                          | Non-consumable (one-time) | 1500 coins, 10 hints, 10 undos, Aurora theme |
| `vip_weekly`, `vip_monthly`             | Subscription              | Entitlement `vip`                            |

RevenueCat: offering `default` with one package per product; entitlements `no_ads` (attach
`remove_ads`) and `vip` (attach both subscriptions). **`starter_pack` must be a non-consumable in
RevenueCat** (otherwise Restore cannot bring its theme back). Full Play Console, RevenueCat and
AdMob steps: [`docs/STORE_CHECKLIST.md`](docs/STORE_CHECKLIST.md).

**Consent testing**: set `EXPO_PUBLIC_UMP_DEBUG_EEA=true`, reinstall the development build (UMP
stores its answer) and reach level 5 on an **emulator**, which UMP treats as a test device
automatically. The debug geography is ignored on physical devices unless their hashed id (printed
by UMP in logcat) is registered as a UMP test device, which this app does not configure.

## Accounts, cloud save and server fulfillment (Firebase)

Optional Google sign-in (Firebase JS SDK + `@react-native-google-signin/google-signin`, no
`google-services.json`) keeps progress in Firestore (`users/{uid}`) and ties RevenueCat purchases
to the Firebase uid. Project creation, SHA certificates, deployment, the RevenueCat webhook, the
Blaze billing note and the emulators: **[docs/FIREBASE_SETUP.md](docs/FIREBASE_SETUP.md)**.

- **Cloud disabled**: without the Firebase api key, auth domain, project id and app id **or**
  `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`, the app logs "Cloud disabled", plays fully as a guest and
  Settings → Account shows "Sign-in unavailable in this build". Nothing Firebase loads.
- **Server fulfillment** (`USE_SERVER_FULFILLMENT` in `src/config/constants.ts`, default `true`,
  needs the Blaze plan): signed-in purchases are granted by the `revenuecatWebhook` Cloud Function;
  guests are granted on the device. `false` grants every purchase on the device.
- **Hosting** (`public/`): `/` landing, `/privacy-policy` and `/terms-of-service` (also served at
  the app's default `/privacy` and `/terms` through rewrites in `firebase.json`),
  `/delete-account` (Google Play account deletion URL), 404.

## Analytics

`src/services/analytics.ts` defines typed events (`track(event, params)`) and an adapter. The
default adapter logs in development builds and does nothing in release builds: **no analytics
vendor and no Crashlytics ship in v1** (the privacy policy and the Play data-safety form rely on
this).

To add a vendor later (for example Firebase Analytics via `@react-native-firebase/analytics`, which
needs a native setup and `google-services.json`, or any HTTP backend):

1. Implement `AnalyticsAdapter` (`track(event, params)`; params are flat strings, numbers and
   booleans) in a new service file, loading the SDK lazily.
2. Install it once at start-up with `setAnalyticsAdapter(adapter)` (for example in the root
   layout's idle callback, after consent if the vendor needs it). Call sites do not change, and
   adapter errors are swallowed.
3. Update `docs/PRIVACY_POLICY.md`, the hosted page and the Play data-safety form before shipping.
